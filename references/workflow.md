# 专业流程与动画计划

本文件用于新素材、新动作或较大绑定调整。小修复只检查与变化有关的部分，不要求每次重做整套流程。

## 动画计划：短，但要能指导制作

先写清当前任务的目的和动作范围，再输出必要姿态与运动关系；不要把空泛的“自然、流畅”当成可执行设计。

```text
目的与观看条件：谁在做什么；视角、实际显示大小、循环/一次性、目标播放器。
关键姿态与阶段：起始 → 预备/蓄力 → 发生/接触/揭示 → 停顿 → 恢复。
运动关系：哪些动、哪些在哪个空间固定、接触与遮挡如何变化、为什么。
结构计划：一起决定切片/补面/层序/支点/骨骼/网格；每个实际风险对应能暴露问题的试姿。
假设和缺项：已知、合理假设、确实会改变做法而需要用户回答的内容。
输出与验收：工程/图层/运行格式；自动检查、目视和目标 runtime 各做什么。
```

使用 SKILL.md 中的五列表即可，不要求另造 JSON 计划格式或一组固定文档。只有实际脚本需要的参数才进入任务配置。

“固定”必须有参考系：手固定在移动道具上，与手固定在世界位置上不同；火球释放前跟随手，释放后沿自身轨迹运动，也属于不同阶段。

## 先查看可复用工程

动作与视角明确后，在自建 rig 前先查用户已有工程、本包已认可样例、官方或其他有来源的同类工程。拿到实际制作文件，在对应编辑器打开，或把标准导出载入真实播放器；看相关动作的起止、接近侧面/极限姿态和遮挡变化，再查看影响这些动作的支点、父子关系、附件、网格/权重、约束、层序或事件。只看 README、宣传成片、格式后缀或安装一个通用库，不能证明已经看过可复用的 rig。

检索来源可包含 Spine、DragonBones 等成熟工程。按角色肢体、柔性效果、投射物、平台或 UI 等实际演出类别找候选，分别核实源格式、可用文件和许可；先在匹配的播放器查看原动作，再决定是否接入。DragonBones 工程不会因进入候选而自动改用另一运行时，Rigby2D 仍是当前制作与预览链路。可查 [DragonBones 实际工程、复用 API 与转换评估](dragonbones-assessment.md#3-开源示例确实有可学习和复用的工程结构)，其中未实测的产品 AI 功能仍只是候选工具。

把独特形象与通用效果分开选材。角色身份、轮廓和风格需要专门设计时，可以生成静态美术；常用火焰、烟雾、爆炸、命中闪光等效果优先选用成熟工程的素材与动作，再匹配画风、喷流/扩散形态、视角、起止阶段和使用许可。新增制作由实际缺口决定，不以所有元素都原创为目标。

在当前动画计划中简记：来源与版本、可用文件及许可、实际查看的动作/时间、准备复用什么、哪些部分不匹配。能适配时在新项目副本中换素材、调整注册和局部动作，保留原工程；需要自建的部分由当前对象或动作的具体差异决定。找不到可用工程时记录实际查到的来源和缺口，再进入最少控制设计，不要求为了套模板改变用户目标。

先区分 Spine 编辑器源项目 `.spine`、运行时导出 `.json/.skel` 与工具自有工程格式。核查目标工具的真实导入入口，并用收到的文件实际读取；“支持 Spine 导出”不能证明能打开 `.spine`。公开可下载的源文件也不等于开源或允许商用，记录明确许可与尚未确认的使用范围。

离线读取器按已验证的版本和结构使用，未知结构显式失败；有配对作者导出时，独立比较实际顶点、RGBA、附件与层序，记录舍入偏差。随包的 [3.8 有界读取器](../scripts/spine38-reader/README.md) 只验证了两个实际工程，不能据版本号推断其他结构都受支持，也不要求每次制作都先分析源文件格式。

复用调查要覆盖本次实际难点。角色绑定和火焰、烟雾等效果分别检查来源：看过龙的骨架，仍需单独打开火焰成品，确认它的轮廓变化、燃烧循环、启动和消散。制作前确认要求包含哪种源工程；需要原生 Spine 效果时，实际查看其骨架、附件、网格变形和关键帧，其他来源封装成 Spine 文件不代表满足了这个要求。成熟效果可用时优先沿用其素材与动作，再调整发射方向、规模和接口。

先保留原图、原动作完成原样播放，再适配角色。来源记录中区分原素材与动作复用、局部修改和组合编排；把火焰挂到嘴部、设置方向、规模及触发时机，属于组合编排。

角色的形象、骨架和动作分别判断能否复用。同结构换皮可沿用已有动作，但要核对骨骼语义与父子关系、参考姿态、长度比例、附件支点和接触位置；“骨名相同”不足以证明动作兼容。增加翅膀、改变肢体结构或明显改变比例时，记录哪些动作和控制继续沿用、哪些需要重定向或另做，再用目标关键姿态检查。参考 [同结构动作替换](https://github.com/DragonBones/DragonBonesJS/blob/64b6c69ae35777c2404be68c9192e2c56906079e/Pixi/Demos/8.x/src/ReplaceAnimation.ts) 与 [换皮](https://github.com/DragonBones/DragonBonesJS/blob/64b6c69ae35777c2404be68c9192e2c56906079e/Pixi/Demos/8.x/src/ReplaceSkin.ts) 的职责划分，不把这类 API 描述为任意骨架自动迁移。

接入时按实际喷口、抓握点或其他接口注册，区分局部坐标与最终世界坐标，检查父级旋转、缩放及镜像是否只计算一次。源发射点随动画移动时，按实际姿态计算注册。合并工程时核对名称、加权骨骼引用、附件和动态层序映射，并保留原动作供对照。启动、持续与收束依据原片段内容编排，避免播完已含消散的动作后又启动循环。具体操作与已验证案例见 [成熟效果复用](native-effect-reuse.md)。

本包 [已认可宝箱](../README.md#已认可宝箱样例) 可作为固定视角硬壳开合的起点：复用下后沿铰链、六面体投影、二维加权网格与动作时间线，再按新素材调整尺寸、相机、材料和事件。其 100 根骨骼与相机数值是当前输出，不是其他对象的配置要求。成品绑定/动作工程、教程、通用工具分开记录；教程中的制作过程和工具提供的能力不能记为已经取得同类成品源工程。

成熟的其他格式工程也可提供可复用结构。比如已有 3D 宝箱的转轴、厚度、动作曲线或相机可以支持最终二维制作；先打开文件并实际查看相关动作，再确定保留哪些关系、怎样转成二维制作源。FBX/GLTF、Spine 导出和编辑器源工程各自记录，页面标注的格式或动画标签不等于已验证文件内容；当前可查入口见 [来源分类](sources.md#同类宝箱工程与参考入口)。

## 先读图，再决定控制

- 确认原图能看见什么、什么被遮挡。单图不能证明隐藏的连接结构；如果不同解释会改变动作，明确解释或提必要问题。
- 看材质、体积、支点、受力和接触，而不只找人体关节点。硬壳保持形状，布料根部跟随连接、自由端有延迟；两者可以用不同控制。
- 将动作预期映射到关键姿态。测试范围来自当前动作，不把每根骨骼都旋转同一角度。
- 若要求明显转面或露出原图未表达的另一侧，先判断需要补哪个视图/部件；不能靠压扁、镜像或扩大遮挡假装已有完整素材。

动作和视角已经明确时直接继续。只有需要新的外形判断或用户选择时才请求补充；先完成可独立进行的分析或静态结果，不把例行确认插在每一步。

## 无图时的静态 master

只读本包 agent-sprite-forge 的 [master-still 静态参考](../vendor/agent-sprite-forge/skills/generate2dsprite/references/master-still.md)，需要组织提示词时再看 [prompt-rules 的静态提示部分](../vendor/agent-sprite-forge/skills/generate2dsprite/references/prompt-rules.md)。借鉴精确身份、参考图角色、构图和局部编辑方法，把主形象及来源保存为之后拆分的依据。

该 vendor 只包含静态参考文本、许可证和版本记录，不是完整可运行 Skill，也不含文中提到的脚本/API。不要执行其中的脚本命令，或跟随 I2V/视频交接链接。固定角色身高、色键背景、描边/高光预设等也不作为通用要求：画风和 alpha 按当前任务选择。

在当前宿主提供 `image_gen` 时使用内置图像工具。将主形象或风格参考通过工具真实支持的图片参数传入，生成后实际查看。不要仅在提示词中写一个文件路径就声称已引用原图。

生成适合当前动作的主形象，确认轮廓清楚、必要部件可辨、四周有活动空间。已有清晰授权和任务信息时可自行作合理设计；需要用户选定新形象时先给可查看的静态结果。用户已经认可的图直接作为 master，不重新要求认可。

局部修补优先编辑已有图，说明哪些可见区域保持、哪些隐藏区域需要新增。分层资产记录原像素、修补像素和生成来源。工具缺失时报告缺口；不要悄悄换为代码重画而宣称保留原画。

上游可能包含 API 优先路由、I2V、视频切片等入口；本工作台使用宿主图像工具和静态分支。当前用户明确选择其他静态来源时按其授权执行。

## 从素材到粗绑定

按独立运动、遮挡关系与连续表面切分。分出来的是“能运动的材料”，不只是静止时刚好拼回去的可见碎片。

AI 或其他拆图工具返回的语义层、隐藏面和层序是候选。头、衣服等语义类别不一定恰好对应运动单元：需要一起变形的连续面可以合并，存在独立转动或遮挡切换的部分才补切。记录原画布坐标、裁剪边界与偏移，按目标姿态检查补面、接缝与负空间，再决定最终颗粒度；不把工具层数上限或返回层数当成推荐骨数。LoongBones 的拆图说明及适用范围见 [评估中的拆图项](dragonbones-assessment.md#ai-拆图与补面值得试用但不能替代动作分析)。

依据动作和视角，一起决定切片边界、补面范围、层序、支点以及骨骼/网格控制。把即将露出的后脑、胸口、木柄或布面补完整，让关节遮盖覆盖预期运动范围。补的是该部件自身的材料，不能复制邻近其他部件的颜色来凑重叠。试姿暴露问题时允许回改这些决定，不把已经切好的图层当作绑定方案的既定边界。

拆件后先按原参考姿态回叠，与 master 对齐地面并采用统一的整体尺度，比较头顶、肩线、腰胯、肘腕、膝踝、整体轮廓与负空间。不能为了共用同一骨架，把各部件分别缩放拼到预设关节点，强行改变原参考比例。双形态本来具有不同身形或比例时，保留各自参考姿态，明确动作重定向或形变安排。整体体态与形象通过静态检查后，再进入动作试姿；这项检查由 AI 自行完成，无需逐步询问用户。

优先完成支撑主动作所需的最少控制。暂时不制作无当前用途的控制器、表情系统或额外动作。将计划中的风险对应到能暴露它的姿态与过渡，例如最大揭露时的补面、极端弯曲时的接缝、支撑物移动时的接触。姿态范围由当前动作决定，包含需要的原始、目标、反向或适度超出需求的状态，不固定图数或骨数。

用同一份粗绑定工程在实际播放器渲染这些试姿，保存可查看画面和工程中的姿态/时间位置。画面记录关联本轮构建清单的 SHA-256、播放器版本与采样方式；静态拼图或骨架线示意只能帮助解释，不能代替真实变形结果。按风险逐项记录看到的问题与局部修正，再用修订后的同一工程复测受影响的试姿；修好接触、体积、遮挡和连接后再细化动作。计划、试姿索引与修正结果可合在现有项目文档，不要求新增一组固定文件或逐步审批。

绑定参考姿态与动画测试姿态分开保存。在测试姿态调整权重后，返回参考姿态复核，避免把编辑时的补偿误当成正确绑定。

## 修图与装配更新

已有动画反复修图时，沿用项目现有的部件标识、文件到附件/slot 的映射、原画布坐标和裁剪偏移，在原部件更新图片。当前 PNG 文件名与附件名已能稳定定位时就沿用，不为同步另建一套通用 ID 系统。不要因为重新导出或重新拆图就给已有部件重新编号、自动居中或改变局部原点。

补画使图片边界变大时，保留原画布中的位置，并更新裁剪偏移与附件注册，使原像素仍落回原位置；参考姿态回叠后，再检查受影响的极限姿态。图片尺寸或网格顶点布局变化时，核对附件尺寸、UV、三角形、权重和变形轨道，不能假定替换 PNG 后旧网格仍然正确。

新部件单独列入本轮装配：说明接到哪根骨骼、哪个 slot、处于什么层序及怎样遮盖；完成实际试姿后再接入现有动作。合并或移除部件时同步核对已有附件引用和动画，不能把源图层增删自动当成动画对象增删。上述处理借鉴 [LoongBones 素材同步](https://github.com/DragonBones/Loongbones-doc/blob/f866e596cc7b7a7fa52e6d5f349d2dc7be237434/zh/loongscales/loongbones-sync.md) 中的稳定引用与新素材明确装配，但不依赖其云服务。

## Blocking 与时间

先让关键姿态、重心、弧线和事件成立，再细化插值。预备动作是为了让发生的动作可理解；停顿让结果可读；恢复服务于一次性结束或下一次动作，不机械套同一节拍。

主动作清楚后再调整衣摆、帽尖、尾迹等次级运动。根据连接和材质产生延迟、重叠或回摆，保留真正该固定的区域，避免通过全身小幅摆动掩盖主动作不清楚。

道具释放、抓握切换、命中与结果揭示需要明确的时间和空间关系。运行时事件应来自同一动作时间线或可解释的同步规则，不能让预览看起来命中了而事件在另一时刻发生。

## 交付前

在真实播放器以实际显示大小检查原速和关键中间帧，再检查循环/恢复与动作切换。必要时输出固定时间采样的预览供复核。交付与证据边界按 [验收](acceptance.md) 记录。

效果必须在实际背景上按原 slot 混合方式检查。出现黑框、发灰或异色边时，依次核对 slot blend、源 PNG 的颜色与 alpha、straight/PMA 约定，以及 canvas 与实际背景的合成，再决定是否需要改图。本例黑底灰度 `gole` 依靠原 additive 显示；修正背景合成即可保留原 PNG。需要透明输出时应验证透明合成，不能把所有画布强制不透明作为通用修复。
