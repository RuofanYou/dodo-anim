# 验收与交付边界

检查与实际风险相称。局部美术修订不必重建无关系统；改变绑定、材质连接或事件时，要重新检查受影响的姿态与动作。

## 验证前先固定输入

记录 master、分层 PNG、骨架、动作和构建入口的版本或哈希，确保导出的 PNG、尺寸、元数据和网格来自同一轮构建。运行中输入变化时，原报告不能作为新版本通过的证据。

工作台自动记录配置、骨架、已用分层 PNG、`sourceImage` 和 `buildScript` 的哈希。动作参数、绑定规格、补面源图、子脚本等额外文件，通过 `workbench.json` 的可选 `inputs` 相对文件路径数组显式列入，例如 `"inputs": ["actions.json", "rig_spec.json", "art/underlay.png", "scripts/build-rig.py"]`。仅列本项目实际使用的文件；不存在的路径会失败，工具不自动解析入口的依赖。

粗 rig 试姿和最终预览都记录实际渲染文件、工程中的姿态/时间、播放器版本及对应 `build-manifest.json` 的 SHA-256。保留该轮清单或可重建的源版本，确保画面能对应到具体的输入哈希；重新构建不会使旧截图自动成为新版本的证据。

区分认可的可见区域、原有隐藏区域和获准修改的轮廓。只有全图确实不变时才能声称逐像素一致；局部补布改变了原图空隙，就应说明该区域的改变。

拆件后先验收原参考姿态回叠：在同地面、统一整体尺度下，与 master 比较头顶、肩线、腰胯、肘腕、膝踝、轮廓和负空间。接缝覆盖不能代替整体体态与形象检查；整体通过后再做动作。检查是否因套用共用骨架而分别缩放部件、改变了原有比例。双形态原本比例不同时，分别对照各自参考，核对已说明的重定向或形变安排，不以统一关节点坐标作为通过条件。

修图更新时，检查既有部件是否仍映射到原附件/slot，原画布位置、裁剪偏移和附件注册是否保持。边界扩展后的旧像素应回到原位置；新增部件核对父级、层序与遮盖。尺寸或拓扑改变时再检查实际受影响的 UV、权重及变形轨道，并复测对应试姿。AI 分层结果只有在这些检查后才能作为可活动素材验收，层数多少不代表拆分质量。

## 自动可以检查的内容

- 文件和标准格式能否读入；骨骼父子关系、附件/图集映射、UV、三角形、权重和尺寸是否有效，缺失引用应明确失败。
- 静止姿态与源图的注册关系；受保护区域的像素/尺寸是否保持，修补区域是否按约定存在。
- 接触点误差、事件时序、循环端点和采样姿态中的数值/几何异常；采样范围、时间步长和容差应随当前动作说明。
- 对实际需要连通的区域，利用真实变形后的几何和 PNG alpha 检查覆盖，包括线性过滤下的亚像素位置；记录区域、阈值、最差位置与帧。

覆盖检测区域来自对象结构和风险点。内部连接通过不能代替外轮廓检查；有意保留的负空间也不应被错误要求为全不透明。新的缺口位于原采样区域之外时，原结论只对原范围有效。

工具返回的退出码、通过项和失败项据实报告。默认 validator 没检查某项，就不把它写为已通过。

复用成熟工程时，检查原动作、原图、曲线、附件切换和动态层序的保留情况，再检查组合后的挂接、父级缩放与触发时段。来源保留和接入正确分开验证；源文件哈希一致不能证明新喷口已对齐。

## 必须看实际画面的内容

在最终显示尺寸和原速下看清主动作，再放大检查容易出问题的交界。至少检查本次动作中的关键姿态和过渡位置，风险较高的连接应看全段。

- 形象、比例、体积、材质和笔触是否保持；补图有无异色边、重复轮廓、拉伸或涂抹感。
- 动作是否能说明谁主动、什么跟随、什么固定；重心、支点、抓握与释放是否符合意图。
- 主动作是否清楚，速度、停顿、回摆与次级运动是否有因果关系。
- 浅色、深色或能显露边缘的背景下检查透明边缘；自动 alpha 全覆盖不证明颜色连续或自然。
- 循环、一次性恢复、切换、快速插值和实际裁切范围是否正确。

不要以骨骼叠加线、静止截图、文件能解析或“所有参数合法”代替这些判断。

检查结构计划中的每项实际风险是否有对应试姿及真实渲染画面，画面是否来自同一粗 rig 的可编辑姿态。发现破绽后应能追溯到切片、补面、层序或绑定的局部修正，以及受影响姿态的复测结果；无需为已通过且未受影响的部分重复制作。

## 目标运行时分别验证

Rigby2D 实际播放能证明该工程在测试版本中的表现。标准 Spine JSON、二进制、atlas、PNG 等导出，各自记录格式与版本；不得只改版本字段就声称完成通用转换。

跨工具或格式接入前，列清源文件和源播放器版本、转换器版本、目标格式与目标播放器版本，以及当前工程真实使用的特性。按实际内容检查网格/权重、FFD/deform、插值曲线、约束及动画约束、附件切换、动态层序、混合、嵌套骨架和事件；未使用的特性不要求补做测试。原格式播放与目标播放采用相同动作和时间对照，离散切换看关键时刻前后，事件还要检查接收端实际触发。目标不支持的特性说明转换、替代或省略及其影响，不能静默丢弃后宣布保真。

DragonBones 标准导出、`.dbproj`、Spine JSON、`.skel` 和 `.spine` 分别核查，旧 Tools 与新版 LoongBones 插件的能力分开记录；某个版本转换器的失败不外推为整个生态不可用，某项成功也不外推为全部特性通过。已知探针与范围见 [DragonBones 转换评估](dragonbones-assessment.md#5-旧-tools有可用实现也有实测转换损失)。

需要检查本工作台的 Spine 4.3 交换结果时，可用 [独立消费比较入口](../validation/spine-consumer/README.md)：通过已锁定的官方 Spine Core 和 rig-c poser 实际加载 JSON 与二进制，在同一动画时间网格比较几何、颜色和绘制顺序。它保留严格失败，不跳过发生差异的关键帧；结果只覆盖给定版本、文件和采样，仍需看实际播放画面。

JSON 小数舍入与二进制 float32 可能使附件、层序或事件的离散切换落在相邻采样步。涉及这些轨道的转换，检查关键时刻之前、时刻本身和之后的状态，分别报告连续几何误差与离散状态差异。保留严格比较失败及时间差，不通过删除边界帧、单纯放宽几何容差或提前移动正确关键帧来取得“完全一致”。

C++/Skia、WebGL、CanvasKit/Skottie 或游戏中的其他播放器分别测试。Skia 可以绘制自研骨骼 runtime 的三角形；Skottie 播放 Lottie；两者不是同一转换链路。未在目标环境加载并看结果时，明确写未验证。

真实页面或游戏集成需在得到当前任务授权后进行；素材工作台的预览不代表已集成、部署或发布。

## 预览与可编辑源

MP4/GIF 是从确定的工程、运行时与时间采样得到的预览。记录输入版本、画布、帧率、背景和动作范围，检查实际解码、时长、裁切和关键帧。

循环视频按 `0 <= t < duration` 采样，不把终点的重复姿态额外算成一帧；一次性动作是否保留结束停留由当前演出决定。编码后完整解码，核对帧数、时长、尺寸和实际海报，并查看启动、持续、收束与边缘裁切。分享用 MP4 可沿用已验证的 H.264、yuv420p、faststart 参数，分辨率、帧率、背景与音轨按任务选择。

工作台通用 CLI 只有 doctor/init/build/validate/preview。巫师样例的 [render-cast 入口](../examples/bean-wizard/scripts/render-cast.html) 使用 Rigby2D 官方 `renderJob`；需要该样例 MP4 时复用已验证路径，不为此增加另一套通用渲染 API。

已有成熟原生效果组合的完整导出可参考 [死亡之翼 MP4 脚本](../examples/deathwing-native-fire/scripts/export_mp4.ts) 与 [360 帧完整解码记录](../examples/deathwing-native-fire/evidence/mp4-export.json)。它保留原 normal/additive，在固定背景与镜头中逐帧渲染；6 秒、1080p、60 fps 只属于该样例。网页与离线视频使用不同渲染路径时，分别记录版本和实际画面，不据共享源文件宣称像素完全一致。

保留可编辑骨架、动作/关键帧、约束、网格/粒子参数、原图与分层、局部修补来源及构建方式。禁止用 I2V、视频扩散、生成视频切帧替代这些制作源。

交付说明可以很短，但分清：

```text
已产出：工程、素材、预览与重建入口。
自动检查：实际检查了什么、结果和报告位置。
目视检查：查看了什么画面/动作/尺寸，尚存什么问题。
用户认可：用户认可的具体版本、形象或动作；不据此扩为其他平台验收。
目标 runtime：测试的播放器与版本、结果；未测试的另列。
来源与改绘：原创、换皮、动作复用、隐藏面修补及使用范围。
```

一个成功角色和局部严格检测不能证明任意角色一次成功。修改应由实际失败或当前需求驱动，通过后停止扩展。
